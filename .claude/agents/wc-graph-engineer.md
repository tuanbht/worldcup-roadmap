## What you must know

- **One continuous canvas, one day axis.** `build-graph.ts#buildRoadmapGraph(tournament, tz?)` is a pure `Tournament → RoadmapGraph` transform. Group + knockout share ONE chronological axis: `layout/day-axis.ts` (`dayKey(iso, tz?)` via `date-fns-tz` `formatInTimeZone`, `orderedDays(matches, tz?)`, `computeDayIndex(matches, tz?)`) maps each match's kickoff to a 0-based day-row. Resolve the timezone ONCE at the top via `resolveTimeZone(tz)` (from `@/lib/datetime`) and thread that concrete `zone` string through every pass — never let a second ambient read drift.
- **Group zone** (`layout/group-layout.ts#computeGroupGridLayout(tournament, dayIndex, zone) → GroupGridLayout`): groups A..L are fixed columns (`columnX` = `RAIL_W + colIndex*GROUP_COL_PITCH`), each match at column×day-row. A (group,day) cell with two distinct kickoffs splits via `subSlotX` to `x ± SLOT/2`; same-kickoff matches STACK vertically at `y ± STACK/2`. Returns `{ matches, headers }`.
- **Knockout funnel** (`layout/bracket-layout.ts#computeKnockoutFunnelLayout(tournament, dayIndex, cx, tz?)`): d3-hierarchy fan-in rooted at the FINAL, children = the two `winnerOf` feeders in [home,away] slot order (`winnerChildrenOf`), so each parent's x is the midpoint of its children. `tree().nodeSize([LEAF_X_PITCH, 1]).separation(() => 1)`; leaves re-centered so leaf-mean == `cx` (=`CX`) and Final lands on `cx`. Y is the REAL day-row from each KO match's kickoff (parent after both feeders ⇒ `parent.y > child.y` ⇒ edges flow downward). THIRD_PLACE sits `x = Final.x + LEAF_X_PITCH`. Throws `'bracket invariant: FINAL round missing'` if no FINAL.
- **Nodes emitted** (`graph-model.ts`): `RoadmapNode = MatchFlowNode | DayMarkerFlowNode | GroupHeaderFlowNode | GroupStandingsFlowNode` (React Flow `Node<Data, typeTag>`). build-graph emits, per match, a `match` card; per distinct day a `day-marker`; per group A..L BOTH a `group-header` (`groupHeaderNode`) AND an always-on `group-standings` (`groupStandingsNode(group, headerXY)`, id `group-standings-<name>`, carries the live `Group` with `table`, anchored at `{ x: headerXY.x, y: STANDINGS_Y }`). `group-header` is STILL emitted — both node types are registered in the UI's `node-types.ts`.
- **Edges** all flow downward with `sourceHandle:'b'` / `targetHandle:'t'` (`HANDLES`). `feederEdges` = one per (group, seeded-R32-slot) via `R32_SEEDING` + `groupExitMatchId` (group's latest-kickoff match), id `feed-<G>-<r32>`, state `'undecided'`. `advanceEdges` = one per non-group bracket slot (child→parent), id `adv-<src>-<tgt>`, state from `edgeState(status)` → `'live' | 'decided' | 'undecided'`. Knockout cards merge live fields (`score/status/kickoff/minute/venue`) from the resolved `Match` via `matchById`, else the unscheduled-slot default (`EMPTY_SCORE`, `'scheduled'`) — never a hardcoded "scheduled" pill on a real game.
- **Display-layer stamps (NOT in build-graph).** `MatchNodeData.isNearest?` and `MatchNodeData.focusState?` / `AdvanceEdgeData.focusState?` are set ONLY by the canvas display layer, never by build-graph, so the graph stays time-independent + memoizable.
  - `apply-nearest-flag.ts#applyNearestFlag(nodes, nearestId)` immutably flags the single `match` node with that id (`isNearest:true`); `null` flags nothing; non-`match` nodes pass through untouched.
  - `team-focus.ts`: `selectTeamFocus(tournament, teamId) → TeamFocus` ({matchNodeIds, edgeIds}) computes the team's match-node ids (resolved home/away) + path edge ids (its group feeders via `R32_SEEDING`, plus `adv-*` edges whose BOTH endpoints are focused) by reconstructing build-graph's id grammar. `applyTeamFocus(nodes, edges, focus)` returns immutable copies stamping `focusState:'on'` on path nodes/edges and `'dim'` on the rest; `null` focus returns shallow-copied inputs unchanged.
- **LOD** (`lod.ts`): `zoomToLod(zoom, prev?) → 'overview' | 'titles' | 'detail'` with hysteresis (`LOD_ENTER` strictly above `LOD_EXIT`). Drives a `data-lod` attribute + CSS opacity, never a re-render. `hooks/useZoomLevel.ts` reads `useStore(s => s.transform[2])` → `{ zoom, lod }`, tracking `prev` in a ref.
- **Camera/state hooks**: `useStageView` is `?focus=` URL state → `{ focus, setFocus }` (`history.replaceState`, hydrate after mount). `useFocusCamera(focus, nodes)` frames subsets via `fitView`/`fitBounds`/`frameTopAligned` + `footprintOf`/`boundsOf`/`isGroupZoneNode`/`isKnockoutNode`. `focus-target.ts#pickFocusMatchId(matches, nowMs)` picks the not-yet-ended match (`kickoffMs + MATCH_DURATION_MS > now`) with smallest estimatedEnd (tiebreak kickoff then id); `useFocusMatch(options?)` centers it with `FOCUS_ZOOM`/`FOCUS_DURATION_MS`. `useFocusedTeam(tournament)` is `?team=CODE` URL state → `{ teamId, teamCode, setFocusedTeam, clear }` (resolves FIFA code→id after the roster lands, toggles off on re-select, preserves a co-existing `?focus=`). `interaction-mode.ts` maps `'zoom'|'pan'` → `interactionFlowProps`/`InteractionFlowProps` (localStorage-persisted via `useInteractionMode` → `{ mode, setMode }`, SSR/no-window-safe via `readStoredMode`/`persistMode`). `useFitOnChange(key, nodes?)` / `useBracketKeyboard(onEscape)` are imperative React Flow helpers.
- **Data hooks (FIFA-direct, no backend)** use TanStack Query v5, focus-only refetch, NO `refetchInterval`:
  - `useTournamentQuery()` — `queryKey:['tournament']`, `queryFn: () => selectRepository().getTournament()` (from `@/data/repository-factory`). Returns `{ data: Tournament | null, loading, error }` (full `Tournament` so the Legend reads `meta.provider`). The shared client (`@/lib/queryClient`) sets `staleTime`/`gcTime` 3s + `refetchOnWindowFocus:true` + `refetchOnReconnect`, no interval.
  - `useMatchDetailQuery(match: Match | null)` — `queryKey:['match-detail', match?.id ?? null]`, `queryFn: ({signal}) => loadMatchDetail(match!, {signal})` (from `@/data/providers/fifa/match-detail-loader`), `enabled: match != null`, `staleTime: 3_000`. Maps `DetailOutcome` (`{kind:'ready',detail}` | `{kind:'unavailable'}`) → `{ detail, status, error }` with `status: 'loading'|'ready'|'unavailable'|'error'`; a null `providerRef` → `'unavailable'` (not an error), a genuine upstream throw → `'error'`. The `AbortSignal` is forwarded so switching/closing aborts in-flight.
- **`useRoadmapGraph(tournament)`** is the only build-graph caller — `useMemo`'d, recomputes only when the tournament changes, returns `EMPTY` for null.
- **Fixtures** (`__test-support__/roadmap-fixtures.ts`): `loadTournament` (re-parsed mock at fixed clock `FIXTURE_AT = '2026-06-17T00:00:00Z'`), `loadBracket`, `groupStageMatches`, `allBracketNodes`, `groupNames`, `groupDayCells`/`groupTwoMatchCells`, `winnerChildren`, `expectedFeederCount`/`expectedAdvanceEdgeCount`, `distinctMatchDays`, `fixtureDayKey`, `koMatchById`, `deepFreeze`, `sortedEntries`. Everything is fixture-DERIVED — never hardcode counts.

## Hard rules

- Immutability everywhere; files <800 lines, functions <50, nesting ≤4; explicit error handling; no hardcoded secrets; no leftover `console.log`.
- Layout/build-graph stay PURE and time-independent — no `Date.now()`, no clock read inside the graph. `isNearest` is injected only by `applyNearestFlag`; `focusState` only by `applyTeamFocus` — both in the display layer.
- One resolved `zone` threaded through all passes; geometry comes from `layout-constants.ts` tokens (`NODE_W/H`, `DAY_MARKER_H`, `*_PITCH`, `SLOT`, `STACK`, `RAIL_W`, `HEADER_H`, `HEADER_TOP`/`GROUP_TABLE_H`/`HEADER_GAP`, `STANDINGS_Y`, `CX`/`centerline`) — no re-hardcoded magic numbers. `HEADER_H` is DERIVED (`HEADER_TOP + GROUP_TABLE_H + HEADER_GAP`); both group and knockout day-rows root at `HEADER_H`, so growing the standings band pushes every row down uniformly. `DAY_MARKER_H === NODE_H`.
- Keep emitting `group-header` AND `group-standings` (both registered). All edges flow downward (`HANDLES`); `parent.y > child.y` must hold. Do not change `MatchNodeData`/`RoadmapNode`/edge shapes (incl. `isNearest`/`focusState`) without coordinating with the UI agent's consumers.
- Data hooks are focus-only refetch with NO `refetchInterval`; call `selectRepository()` / `loadMatchDetail` — never reintroduce an `/api` fetch or transport envelope. Boundary zod validation lives in the data layer; consume already-validated domain types.
